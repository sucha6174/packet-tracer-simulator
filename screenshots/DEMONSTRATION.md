# Virtual Network Simulator - Demonstration & Test Execution Evidence

This document provides verified demonstration evidence of the Virtual Network Simulator processing simulated network packets across all fundamental operational and edge-case scenarios.

Each test below reflects actual execution results generated by `npm run demo` and automated API tests against the running server.

---

## Summary of Demonstration Scenarios

| Test Case | Scenario | Focus Area | Result | Steps |
|---|---|---|---|---|
| **Case 1** | `scenario-basic` | Happy Path (DNS -> Route -> TTL -> Firewall -> Forward) | Forwarded | 4 |
| **Case 2** | `scenario-basic` | DNS Failure (NXDOMAIN) | Dropped at DNS | 1 |
| **Case 3** | `scenario-complex` | Routing Failure (No Route to Host) | Dropped at Router | 1 |
| **Case 4** | `scenario-basic` | TTL Expiration Boundary (`initial_ttl = 1`) | Dropped at Router | 3 |
| **Case 5** | `scenario-basic` | Explicit Firewall Denial (SSH port 22 blocked) | Dropped at Firewall | 3 |
| **Case 6** | `scenario-complex` | Longest Prefix Match (/32 host vs /24, /16, /8) | Forwarded | 3 |
| **Case 7** | `scenario-complex` | Multi-Level CNAME Chain Resolution | Forwarded | 6 |
| **Case 8** | `scenario-basic` | Firewall Default-Deny Policy | Dropped at Firewall | 3 |

## Detailed Execution Evidence

### 1. Test Case 1: Successful Packet Tracing (Happy Path)
- **Description:** A valid packet destined for `api.example.com` on HTTPS port 443 with `initial_ttl: 5`.
- **Command:**
  ```bash
  curl -X POST http://localhost:8080/trace \
    -H "Content-Type: application/json" \
    -d '{
      "source_ip": "192.168.1.100",
      "destination": "api.example.com",
      "destination_port": 443,
      "protocol": "TCP",
      "initial_ttl": 5
    }'
  ```
- **Response (`200 OK`):**
  ```json
  {
    "trace": [
      {
        "step": 1,
        "component": "DNS",
        "action": "Resolved api.example.com to 10.0.1.50"
      },
      {
        "step": 2,
        "component": "Router",
        "action": "Route matched: 10.0.1.0/24 via 192.168.1.1 on eth1 (prefix /24). Decremented TTL to 4"
      },
      {
        "step": 3,
        "component": "Firewall",
        "action": "Packet allowed by rule 3 (source: 192.168.1.0/24, port: 443, protocol: TCP)"
      },
      {
        "step": 4,
        "component": "Router",
        "action": "Packet forwarded to next hop 192.168.1.1 via interface eth1"
      }
    ]
  }
  ```

### 2. Test Case 2: DNS Failure (NXDOMAIN)
- **Description:** A packet destined for an unlisted domain `nonexistent-host.example.com`. The simulator immediately terminates packet traversal at DNS without attempting routing or firewall evaluation.
- **Command:**
  ```bash
  curl -X POST http://localhost:8080/trace \
    -H "Content-Type: application/json" \
    -d '{
      "source_ip": "192.168.1.100",
      "destination": "nonexistent-host.example.com",
      "destination_port": 80,
      "protocol": "TCP",
      "initial_ttl": 5
    }'
  ```
- **Response (`200 OK`):**
  ```json
  {
    "trace": [
      {
        "step": 1,
        "component": "DNS",
        "action": "NXDOMAIN: Domain 'nonexistent-host.example.com' not found"
      }
    ]
  }
  ```

### 3. Test Case 3: Routing Failure (No Route to Host)
- **Description:** In `scenario-complex`, default route `0.0.0.0/0` is intentionally omitted. A packet addressed to `192.0.2.1` does not match any CIDR block in `routes.json`.
- **Command:**
  ```bash
  curl -X POST http://localhost:8080/trace \
    -H "Content-Type: application/json" \
    -d '{
      "source_ip": "10.0.0.1",
      "destination": "192.0.2.1",
      "destination_port": 80,
      "protocol": "TCP",
      "initial_ttl": 5
    }'
  ```
- **Response (`200 OK`):**
  ```json
  {
    "trace": [
      {
        "step": 1,
        "component": "Router",
        "action": "No route to host: destination 192.0.2.1 does not match any configured route"
      }
    ]
  }
  ```

### 4. Test Case 4: TTL Expiration Boundary
- **Description:** Packet enters router with `initial_ttl: 1`. Router decrements TTL to 0. The packet is dropped immediately with `Time to Live exceeded` before firewall inspection.
- **Command:**
  ```bash
  curl -X POST http://localhost:8080/trace \
    -H "Content-Type: application/json" \
    -d '{
      "source_ip": "192.168.1.100",
      "destination": "api.example.com",
      "destination_port": 443,
      "protocol": "TCP",
      "initial_ttl": 1
    }'
  ```
- **Response (`200 OK`):**
  ```json
  {
    "trace": [
      {
        "step": 1,
        "component": "DNS",
        "action": "Resolved api.example.com to 10.0.1.50"
      },
      {
        "step": 2,
        "component": "Router",
        "action": "Route matched: 10.0.1.0/24 via 192.168.1.1 on eth1 (prefix /24). Decremented TTL to 0"
      },
      {
        "step": 3,
        "component": "Router",
        "action": "Time to Live exceeded. Packet dropped."
      }
    ]
  }
  ```

### 6. Test Case 6: Longest Prefix Match (LPM) Demonstration
- **Description:** Destination IP `10.1.2.50` matches `10.0.0.0/8`, `10.1.0.0/16`, `10.1.2.0/24`, and `10.1.2.50/32`. The router selects the most specific `/32` route.
- **Command:**
  ```bash
  curl -X POST http://localhost:8080/trace \
    -H "Content-Type: application/json" \
    -d '{
      "source_ip": "10.100.0.50",
      "destination": "10.1.2.50",
      "destination_port": 443,
      "protocol": "TCP",
      "initial_ttl": 8
    }'
  ```
- **Response (`200 OK`):**
  ```json
  {
    "trace": [
      {
        "step": 1,
        "component": "Router",
        "action": "Route matched: 10.1.2.50/32 via 10.1.2.50 on eth-host-direct (prefix /32). Decremented TTL to 7"
      },
      {
        "step": 2,
        "component": "Firewall",
        "action": "Packet allowed by rule 4 (source: 10.0.0.0/8, port: 443, protocol: TCP)"
      },
      {
        "step": 3,
        "component": "Router",
        "action": "Packet forwarded to next hop 10.1.2.50 via interface eth-host-direct"
      }
    ]
  }
  ```
